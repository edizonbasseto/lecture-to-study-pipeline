<objective>
Update the native provisioning script for the gateway's local adapter: build checks for `llama-completion` and `llama-tokenize` (D-17, D-23), and an opt-in step that downloads the documented example model with SHA-256 verification (D-06, D-24). This plan touches no Python source and runs in parallel with 06-01.

Purpose: the D-07 manual real-model run (06-11) and Phase 7 need a reproducible way to obtain the engine binaries and the example model; runtime stays offline because downloading happens only here, by explicit operator choice.
Output: updated `scripts/01_provision_engines.sh`, a network-free test of its argument handling and pinned values.

Execution-time verification required by D-24: before writing the download step, fetch the model card and file listing of the Hugging Face repository `Qwen/Qwen2.5-14B-Instruct-GGUF` (repository id is an assumption to verify; the shard file names and SHA-256 values already pinned in the script's `LLM_MODEL_SHARDS` array are the reference). Confirm the three shard names, compare each shard's published LFS SHA-256 with the pinned value, read the license identifier from the model card, and read the repository's current commit SHA to pin the download revision. Stop and report without writing the download step if the page cannot be fetched, any name or SHA-256 differs, or the license is anything other than Apache-2.0 or MIT; in that case the operator decides. Record the evidence (URLs fetched, license text identifier, revision SHA, the three SHA-256 matches) in the SUMMARY for ADR 0046.

Execution rules: invoke `clean-code` before editing the script and the test (R0.3). Script comments in formal en-US. No absolute home paths; the script already derives `ROOT_DIR` from its own location.
</objective>
