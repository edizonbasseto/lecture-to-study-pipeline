Create the documentation checker that makes DOC-02 mechanical: every command the README and the docs name must exist as written (D-03). The checker is a standard-library-only script with unit tests, a make target and a real-repository test, so the later documentation plans of this phase are gated by it and CI keeps them honest afterwards.

Keep each function short and single-purpose, rules as small named predicates, rule names as module constants.
</objective>

Create `scripts/check_documentation.py` (per D-03). Standard library only; module docstring first stating purpose (static check that the commands, paths, links and ADR numbers a document names exist as written, that quoted passages come from the ADRs and that no machine-specific path appears), what is knowingly not checked (flag semantics, program behavior, external programs), and the exit codes; then `from __future__ import annotations`. It imports nothing from `lecture_study`, reads files only and starts no process. Module constants hold the rule names and the exit codes (0 clean, 1 findings, 2 unreadable input).

Tracer slice, one path through every layer: markdown text, fenced command lines, Makefile facts, finding, report, exit code. Implement:
- `Finding`, `MakefileFacts`, `CommandLine` and `Report` as frozen slotted dataclasses. `Finding.render()` returns "document:line: rule: detail".
- `read_makefile_facts(makefile_text)`: a target is a name at the start of a line followed by one colon that is not part of `:=`, and does not start with a dot; a variable is a name at the start of a line followed by `=`, `?=`, `:=` or `+=`. Recipe lines (tab-indented) and the continued `.PHONY` lines are not facts.
- `fenced_command_lines(markdown_text)`: commands inside fenced blocks whose info word is bash, sh, shell, zsh or console. Backslash continuations are joined into one command that reports the first physical line number; a leading "$ " prompt is removed; blank lines and comment lines are dropped; in console fences only lines that start with the prompt are commands. Other fences (mermaid, yaml, text, unlabeled) are ignored. Words come from the standard-library shell splitter with punctuation characters enabled, and commands chained with `&&`, `||`, `;` or `|` are split into separate `CommandLine` values. When the splitter rejects a line, its `CommandLine` carries an empty `words` tuple, and the checking step turns an empty-words command into an `unparseable-command` finding.
- The make rule: every word after `make` that starts with a dash is ignored; a word of the form NAME=value needs NAME among the Makefile variables (rule make-variable); every other word needs to be a Makefile target (rule make-target). Several targets on one line are each checked.
- `check_documents(root, documents)` loading `root/Makefile` and each document relative to the root, and `main(argv)` with `--root` (default: the repository root derived from this file's location) and positional document paths (default: README.md). `main` prints one rendered line per finding, then one summary line "documentation check: D document(s), C command line(s), F finding(s)", and returns the exit code. A missing Makefile or an unreadable document returns 2 with a message on stderr that names the relative path only.

Create `tests/test_check_documentation.py` (module docstring naming DOC-02; plain assert, test classes per unit, `tmp_path`, no sleeps). Load the script by path with importlib as `tests/test_denylist_scan.py` does and register it in `sys.modules` before executing it, as `tests/demo/conftest.py` does. Tests: `read_makefile_facts` on a sample Makefile text with a continued `.PHONY`, a `NAME ?= value` variable, a `HOOKS := a b` variable, two targets with recipes whose lines contain colons; `fenced_command_lines` for a bash fence with a continuation (first physical line number), a prompt, a comment, a mermaid fence that is ignored, a console fence whose output line is ignored, and a chained `&&` line that yields two commands; the make rule for an unknown target, an unknown variable, a dash option that is ignored and two targets on one line; and the tracer test of the whole path: build a minimal repository in `tmp_path` (a Makefile with targets build and demo-run and the variable ADAPTER, plus a README with a bash fence), run `main` through the standard-library process runner as a child of `sys.executable` with `--root` pointing at the temporary repository, and assert exit 0 for a README whose commands exist, exit 1 with the rule name and the missing target in the output for a README naming a target that does not exist, and exit 2 when the README is absent.

Command normalization before classification: drop leading NAME=value assignment words, drop a leading `uv run`, then classify by the first word: `make`; `python` or `python3` followed by either `-m MODULE` or a script path; `sh` or `bash` followed by a script path; or a first word that itself contains a slash (a script invoked directly). A word already judged by the script or module rule is not reported a second time by the path rule.

Script rule: the script path is relative to the root with a leading "./" removed; a missing file is script-missing; each word that starts with two dashes (the part before "=" for `--name=value`) must occur as plain text in the script file, else flag-missing. Module rule: the dotted name maps to `src/<name with dots as slashes>.py` (a package directory with `__init__.py` also counts); a missing file is module-missing; the first non-option word after the module name must occur in the module text between single or double quotes, else subcommand-missing; long options follow the same flag-missing rule. The flag and subcommand checks are textual presence checks, not argparse introspection; the module docstring says so.

Path, link, ADR rules over the whole document text (fences included): the tracked roots and exemptions listed in the behavior block live in named module constants. Link targets resolve relative to the directory of the document; a resolved path that leaves the root counts as path-missing. ADR numbers resolve by globbing docs/decisions. Quote rule: build the folded decision text once per run (NFC-normalized, each line stripped of a leading ">" marker, whitespace collapsed) and fold each passage the same way. Hygiene rule: one compiled expression for the three home-path prefixes; the finding detail names the rule and the line, never the matched path. Finding details name at most the missing token itself, never document content around it.

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-08-01 | Tampering | check_documentation.py command handling | medium | mitigate | Static analysis only: the script starts no process, opens no socket and imports no project package; an acceptance grep and the tracer test pin this; documented commands are never run by the checker |
| T-08-02 | Information disclosure | checker output | medium | mitigate | A finding names the rule, the line and the missing token only; the machine-path finding never echoes the matched path; no document content around a token is printed |
| T-08-03 | Tampering | link and path resolution | medium | mitigate | A resolved path that leaves the repository root is reported as path-missing, so a crafted link cannot probe files outside the root |
| T-08-04 | Repudiation | quote rule | medium | mitigate | A blockquote must occur verbatim in docs/decisions after whitespace folding; an invented or drifted ADR statement fails the check |
| T-08-05 | Denial of service | regular expressions over documents | low | accept | Inputs are repository-controlled markdown of a few hundred lines; expressions are linear patterns without nested quantifiers |
| T-08-SC | Tampering | npm/pip/cargo installs | low | accept | No package is installed (standard library only); acceptance checks that pyproject.toml and uv.lock are unchanged |
