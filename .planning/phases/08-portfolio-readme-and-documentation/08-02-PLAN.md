<objective>
Write `docs/operations.md`, the one document that states the operating boundaries the ADRs impose on this pipeline and its study site (DOC-03, D-02). The README links to it (plan 03).

Purpose: a technical reader or recruiter must be able to see, in one place and in the ADRs' own words, what the system refuses to do, what it leaves to the operator, and what has been accepted as a risk. The document makes no claim beyond the ADRs.
Output: `docs/operations.md`.

Execution rules: invoke the `documentation-writer` skill for structure if available, and keep the `clean-code` mindset of short, single-purpose sections (R0.3 governs code; this plan writes no code). Formal en-US, impersonal voice (no second person, no first-person plural), no emojis (language rule of the operator). Terminology: the document says "stage N" for pipeline stages and notes once that the ADRs call them "Phase N". Blockquotes are reserved for verbatim ADR passages: they are case-sensitive, must stay inside one paragraph of the ADR, and are verified by `scripts/check_documentation.py`; everything else is prose written against the ADR text.
</objective>
